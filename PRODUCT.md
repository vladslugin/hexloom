# Product

## Register

product

## Users

Hexloom serves solo game developers, technical artists, small independent
teams, and curious creators who want to direct AI-assisted game production
without surrendering technical control. They may be comfortable with a
terminal, but they should not need to understand every provider protocol or
build-system detail. Their primary job is to move an idea from intent to a
tested, playable Godot project while seeing which agent changed what and why.

## Product Purpose

Hexloom is an AI-first game creation studio where specialized local agents
generate code, mechanics, textures, models, tests, and project context through
one coherent workspace. It exists to turn disconnected CLI tools into a
directable production system that remembers the visual and mechanical language
of previous games. Success means a creator can describe a change, watch the
work unfold, inspect the artifacts and decisions, test the result, and keep
shipping the same project across desktop and mobile.

## Brand Personality

Technical, audacious, and welcoming. Hexloom should feel like a serious
instrument built by people who love game tools: precise enough to trust,
dramatic enough to enjoy watching, and friendly enough to invite exploration.
The emotional goal is controlled momentum. The creator should feel powerful,
informed, and eager to make the next move.

## Anti-references

Avoid generic neon cyberpunk dashboards, fake walls of terminal noise, Matrix
rain, crypto-trading interfaces, glassmorphism, identical SaaS card grids, and
decorative AI animations that imply activity without explaining it. Hexloom
must not resemble a movie prop, a reskinned chat application, or an admin
dashboard with green text.

## Design Principles

1. **Show causality.** Every agent action connects intent, execution, artifact,
   verification, and outcome so the creator always knows why the project
   changed.
2. **Keep the operator in command.** Automation proposes and performs work,
   while scopes, permissions, interruptions, diffs, and approvals remain
   visible and understandable.
3. **Make density legible.** Hexloom can expose substantial technical detail,
   but hierarchy, grouping, and progressive disclosure must make the next
   action immediately clear.
4. **Earn the spectacle.** Visual energy comes from real builds, agent events,
   generated artifacts, and test results rather than ornamental effects.
5. **Remember the world.** Style, mechanics, constraints, and prior decisions
   behave as durable project memory shared across agents.

## Accessibility & Inclusion

Target WCAG 2.2 AA contrast for text and controls. Never encode status through
color alone: pair color with labels, symbols, and position. Support full
keyboard navigation, visible focus, scalable UI text, reduced-motion behavior,
and layouts that remain usable on compact laptop screens. Dense technical
language should be accompanied by plain-language outcomes where practical.
